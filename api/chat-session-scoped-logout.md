# B7 로그아웃된 인증 세션의 채팅 참여 종료

## 담당 범위

채팅은 인증 담당 모듈의 폐기 확정 알림을 받아 같은 userId/sid의 참여만 종료한다.
로그아웃 API·세션/토큰·쿠키 폐기·공유 인증 저장소는 수정하지 않았다.
인증 담당 코드까지 수정했던 미커밋 변경은 사용자 요청으로 원복했다.

## 인증 담당자 연동 계약 — 적용 전 필수

- 이벤트: `com.muse.meomuneum.chat.connection.ChatSessionLogoutEvent(Long userId, String authSessionId)`.
- 인증 모듈이 서버에서 검증한 사용자와 폐기된 sid로 발행한다. 클라이언트 임의 sid를 신뢰하지 않는다.
- 인증 세션 폐기를 확정한 다음 발행한다. 실패 시 재전달 가능하도록 인증 담당자와 처리 방식을 협의한다.
- userId 또는 정규 UUID sid 누락은 이벤트 생성 시 거절한다. 사용자 ID만으로 전체 종료하지 않는다.
- 기존 `auth.application.ChatLogoutEvent(userId)`의 채팅 수신을 제거했다. **현재 로그아웃 API는 이 구형 이벤트를 발행하므로, 이번 변경만 배포하면 로그아웃에 의한 서버 채팅 종료가 연동되지 않는다.** 새 이벤트 발행을 인증 담당자가 반영한 뒤 함께 배포한다.
- 이 문서의 이벤트는 채팅에서 제공하는 연동 계약이며 인증 담당자의 실제 발행 코드 반영·운영 합의는 미완료다.

## 채팅 처리

단일 서버의 기존 참여 임계 구역에서 해당 userId/sid를 차단하고 모든 참여 행을 종료한다.
이전 종료 행에 남은 runtime 예약·열람 구간도 정리하기 위해 해당 세션의 참여 전체를 조회한다.
동일 세션 registry의 연결 및 참여별 presence·예약·단절 유예·view를 정리하고
WebSocket 4100 / `CHAT_LOGGED_OUT`으로 종료한다. 반복 이벤트에도 다른 sid는 유지한다.
계정 전체 퇴장 메서드는 제재 등 기존 경로를 위해 보존한다.
다른 기기가 같은 방에 남아 있으면 계정 인원은 그대로 유지한다.

채팅 로컬 차단 목록은 입장·CONNECT·활성 연결 권한 검사에 적용한다.
현재 access token 최대 수명 + 60초간 보존하고 주기적으로 제거한다.
메모리 정보이므로 재시작 후 폐기 토큰 차단·refresh 거절은 인증 모듈에서 보장해야 한다.
인증 저장소 조회·폐기 로직을 채팅에서 대신 구현하지 않았다.
공개 REST 계약·DDL·Flyway·환경 변수 변경은 없다. 내부 이벤트 소비 계약만 바뀐다.

## 프론트 연동

FE는 서버의 `CHAT_LOGGED_OUT` 종료를 표시하고 전송/자동 복구를 중단한다.
기존 인증 토큰 제거·만료 이벤트에서도 참여와 화면 메시지를 정리한다.
탭 간 인증 상태 전파·토큰 삭제는 인증 담당 모듈의 책임이다.
다른 기기의 FE 인증 상태는 이 이벤트로 변경하지 않는다.

## 검증

- 채팅 회귀 177개 중 174개 통과 / 실제 FE 실행 조건부 3개 제외. 실제 MySQL9.7.0·WebSocket 포함.
- 같은 sid 두 탭 종료, 다른 sid 송수신·열람 유지, 종료 view 정리, 반복 이벤트·예약·새 로그인 보존 확인.
- bootJar 및 Checkstyle main 통과. 채팅 Java 전체 Spotless는 임시 init script로 대상만 좁혀 통과했다. 저장소 검사 설정은 변경하지 않았다.
- 원본 전체 Spotless는 기존 인증/설정 5개 파일 위반, Checkstyle test는 기존 LocalMockLoginServiceTest.java:40 길이121자 위반으로 실패. 자동 포맷된 기존 5개 파일은 원복했다.
- 원본 clean test bootJar도 시도했다. 외부 로컬 DB 접속 실패와 인증 Hazelcast 진단 테스트 실패가 확인됐고, 인증 테스트의 Hazelcast 초기화 구간이 오래 지속돼 전체 실행은 중단했다. 전체 suite 완료·통과로 표시하지 않는다.
- 전체 실행의 중단 시점 binary 결과와 thread dump는 build/b7-chat-logout-verification/full-interrupted*에 보존한다. 최종 채팅 XML은 같은 디렉터리의 final-chat에 보존한다.
- 최초 추가 테스트의 이메일이 DB 길이를 초과해 실패한 부분은 짧은 fixture로 수정하고 채팅 회귀를 재통과했다.
- 기능043c84d / 검증326bbdf. 인증 코드·공유 인증 저장소·운영 로그인·브라우저 탭 동기화는 변경/검증 완료 범위가 아니다.
실제 로그아웃 API·운영 쿠키·탭 동기화까지의 검증은 인증 담당자의 새 이벤트 연동 후 수행한다.

## 적용·롤백

인증 이벤트 발행 변경과 함께 검토·배포한다. 채팅 변경만 단독 배포하지 않는다.
기존 코드로 롤백하면 사용자 단위 전체 채팅 종료가 다시 적용되므로 인증 담당자와 함께 되돌린다.
DB 변경이 없어 데이터 역마이그레이션은 없다.
