# 지역 채팅 접속 인원 계약

BE #152 / FE #134. 2026-10-08 사용자 확정: 실제 WebSocket 연결이 하나 이상 있는 계정 수를 표시한다. 같은 계정의 여러 연결은 1명이다. 입장 예약과 마지막 연결 종료 후 30초 유예는 표시에서 제외하며 기존 25명 정원 판정에는 계속 포함한다.

## 조회와 변경 알림

별도 REST 조회 없이 인증된 `/topic/chat-rooms/{room_id}` 구독의 최초 이벤트가 현재 인원 조회를 제공한다. 단순 브로커에 실제 구독이 등록된 뒤 해당 구독에 스냅샷을 보낸다. 다른 방 또는 미참여 구독은 기존 인증 규칙으로 거부한다.

```json
{"type":"CHAT_PRESENCE","data":{"room_id":700,"connected_count":2,"version":3}}
```

- `connected_count`: 0~25의 정수. 메시지와 같은 방 topic으로 전달한다.
- `version`: 방별 변경 순번인 0 이상의 정수. 차이값이 아닌 최신 전체 인원을 전달한다.
- 최초 연결/마지막 연결 종료, 실제 퇴장, 지역 이동, 로그아웃·탈퇴, 제재로 인원이 달라질 때 발행한다. 동일 계정의 추가 연결/일부 연결 종료에는 발행하지 않는다.
- 입장·퇴장 상태 변경, 스냅샷과 수신 구독자 확정은 같은 레지스트리 잠금 안에서 처리한다. 구독 등록 사이에 발생한 변경도 스냅샷에 반영한다.
- 비동기 outbound 전달 순서가 뒤집혀도 FE는 같은 연결 세대에서 더 큰 version만 반영한다. 종료된 참여와 구독은 outbound 권한 검사로 제외한다.
- 서버 재시작은 메모리 연결·순번을 초기화한다. 재연결한 FE는 이전 인원·순번을 지우고 새 스냅샷을 기다린다. DB의 열린 참여를 실제 연결로 계산하지 않는다.

## FE 상태

입장 중에는 인원 확인 중, 단절 시에는 연결 끊김, 준비 후 10초 동안 스냅샷을 받지 못하면 인원 확인 실패를 표시한다. 이전 인원이나 임의의 0명을 표시하지 않는다. 다음 정상 이벤트를 받으면 복구한다. 다른 방, 지난 연결 세대, 낮거나 같은 순번, 유효하지 않은 값을 버린다.

## 검증

- 레지스트리 테스트: 예약/유예 제외, 계정 중복 제거, 변화 없는 연결 종료, 재연결, 종료된 참여 스냅샷 제외, 26명 동시 접속 시 실제 연결 25명.
- 실제 WebSocket 통합 테스트: 초기 스냅샷, 1→2→1 변경, 같은 계정 여러 연결, 재연결 스냅샷, 다른 방 격리, 명시적 퇴장.
- 기존 #141 회귀: 실제 2인 메시지·ACK, 전송 차단, 계정 전체 제재 및 만료 경계.
- 격리된 MySQL/BE와 FE의 실제 STOMP 라이브러리·이벤트 파서 연동: 초기 인원, 1→2→1, 계정 중복 제거, 텍스트 전달·ACK 통과. 가상 계정만 사용했다.
- 전체 BE 검증: Spotless, Checkstyle main/test, 테스트 448개 중 429개 통과·19개 조건부 제외, bootJar 통과.

DB 스키마 변경 없음. 공동 음악 재생·참여자 목록·과거 채팅 조회는 포함하지 않는다. BE 이벤트 배포 후 FE를 배포하며, 구버전 BE에는 FE가 인원 확인 실패를 표시한다.
