# 지역 텍스트 채팅 초기 탐지 기준

BE #141 / FE #134의 사용자 검토 결과를 기록한다. 예문 번호와 전화번호는 테스트용 가상 값이다.

## 현재 정책 — #155, 2026-10-10 사용자 확정

욕설·음란성은 전송 거절·자동 제재·강제 퇴장 없이 탐지된 구간을 마스킹하여 저장·방송·ACK한다. 공백·300자 제한·URL·개인정보·전송 간격·동일 내용 세 번째 전송 차단은 유지한다.

- 문자: 탐지 구간의 입력 Unicode code point 수만큼 `*`. `씨발` → `**`, `개새끼` → `***`, `씨@발` → `***`, `자지 빨아` → `*****`.
- 인용·가사에도 적용한다. 나머지 본문·공백·이모지와 Unicode 조합은 보존한다.
- 탐지용으로만 NFC 정규화한다. 겹치는 탐지 구간은 합집합으로 마스킹해 라이브러리 HashSet 순서에 의존하지 않는다.
- 글자 사이의 공백(Unicode 공간·줄바꿈 포함)과 `@`, `_`, `-`, `.`, `*` 삽입을 지원한다. 탐지 구간 안의 공백·기호도 마스킹한다. `#`, 숫자 삽입·유사 글자·미등록 표현은 추정하지 않는다. 영어는 대소문자를 구분한다.
- 제외 단어는 탐지 목록에서 제거한다. 허용 문구는 앞에 다른 문자·숫자가 붙지 않은 정확한 문구만 보호한다. 허용 문구의 공백·기호 변형을 자동 확장하지 않는다.

### 라이브러리와 목록 검토

[bad-word-filtering](https://github.com/VaneProject/bad-word-filtering)의 Maven Central 배포 `io.github.vaneproject:badwordfiltering:1.0.0`을 Java 25에서 검증·고정했다. MIT 라이선스이며 의존성으로 사용한다. 배포된 sources JAR의 실제 `BadWords`와 `BadWordFiltering` 구현을 검토했다. 변경되는 웹 목록을 런타임에 조회하지 않는다.

기본 고유 표현 599개에서 일반 단어·모호한 짧은 표현·중립 정체성/의학 용어 56개를 제외했다. 서비스 표현 4개를 추가했고 공백·기호 정규화 및 중복 제거 후 실제 탐지 키는 545개다. 기본 목록을 서비스 정책으로 그대로 채택하지 않는다.

파일은 UTF-8, 한 줄에 한 표현이며 `#`로 시작한 줄은 주석이다. 기동 시 로딩하며 변경에는 재시작·재배포가 필요하다. 파일 누락·빈 항목·중복·알 수 없는 제외 항목은 기동 실패로 처리한다.

- 추가: `src/main/resources/chat/moderation/additions.txt` — `개새끼`, `자지 빨아`, `보지 빨아`, `보지빨아`.
- 제외: `src/main/resources/chat/moderation/exclusions.txt` — 전체 56개가 정책의 검토 가능한 목록이다. 공지/공지사항/운영자/마스터, 게이/동성애자/트랜스젠더, 고환/유방/성교/성폭행, 날짜와 충돌하는 18년, 새끼/보지/자지 등 모호한 단독 표현을 제외한다. 포함 문구가 모두 제외되는 것은 아니다.
- 허용 문구: `src/main/resources/chat/moderation/allowed-phrases.txt` — 시발점, 새끼 고양이/새끼고양이, 호모 사피엔스/호모사피엔스.
- 새 단어·예외는 정상 문장과 대상 문장 테스트를 함께 검토한다. 사전 기반이라 모든 문맥의 오탐·우회를 해결하는 방식은 아니다.

| --- | --- |
| 가사에 씨발이 있어 | 가사에 **이 있어 |
| 씨@발 개새끼 😀 | *** *** 😀 |
| 씨발병신 | **** |
| 자지 빨아 | ***** |

| 게이 동성애자 트랜스젠더 / 고환 유방 성교 성폭행 성교육 | 원문 유지 |
| 시발점에서 시작해요 / 새끼 고양이가 귀여워요 | 원문 유지 |

| 씨#발 / 씨1발 | 미지원 우회, 원문 유지 |
| 씨발 https://example.com / 씨발 010-0000-0000 | 원문에 기존 차단 규칙 적용, 저장·전달 없음 |

### 검사 순서와 재전송

연결·참여·구독 권한 → JSON/UUID/입력 검증 → 기존 UUID 확인 → 원문 도배/개인정보 검사 → 마스킹 → DB 커밋 → 동일 저장 결과를 방송·ACK한다. 처리 중 원문을 로그나 별도 저장소에 추가로 저장하지 않는다. 기존 인메모리 반복/UUID 판정에는 원문 SHA-256만 사용한다.

성공한 같은 UUID·같은 원문 재전송에는 저장된 마스킹 ACK만 돌려준다. 서로 다른 원문은 마스킹 결과가 같아도 UUID 재사용을 허용하지 않는다. 서버 재시작/다른 참여의 UUID 재사용 제한은 유지한다. 반복 제한은 기존대로 동일 입력 원문을 기준으로 한다.

FE는 현재 방·참여·인증 사용자·전송 UUID를 확인해 마스킹 ACK로 대기 원문·타이머를 정리한다. ACK와 broadcast 순서와 상관없이 같은 저장 결과를 한 번 표시한다. ACK 미확인 재전송에는 원래 UUID·원문을 사용한다.

### 기존 제재 해제와 배포

사용자 결정으로 기존 욕설·음란성 자동 제재도 해제한다. 새 마이그레이션 `V20261010155558__release_legacy_automatic_chat_bans.sql`은 활성 상태·자동 등록(`banned_by_user_id IS NULL`)·대상 사유인 행의 `deleted_at`만 UTC 시각으로 기록한다. 제재 행·사유·시작·만료와 참여 이력은 보존한다. 수동 등록, 이미 만료·해제된 행과 미래 시작 행은 변경하지 않는다. 스키마 변경 없음. 기존 입장·연결의 제재 검사도 유지한다.

FE 호환성 변경을 먼저 배포한 다음 기존 BE를 중지하고 새 BE·마이그레이션을 적용한다. 기존 BE가 동시에 실행되면 자동 제재가 다시 만들어질 수 있으므로 혼용하지 않는다. 해제된 제재를 롤백만으로 재활성화하지 않는다. 구버전 BE로 복귀하면 신규 자동 제재 정책도 돌아오므로 정책 확인 없이 롤백하지 않는다. 운영 DB에는 이 작업에서 직접 접근하거나 해제를 실행하지 않았다.

현재 설정은 `CHAT_MESSAGE_MINIMUM_INTERVAL` 기본 `1s`와 `CHAT_PERSONAL_CONTENT_DETECTION_ENABLED` 기본 `true`다. `CHAT_AUTOMATIC_BAN_ENABLED`와 YAML profanity/obscenity 항목은 제거했다. 마스킹은 항상 적용한다.

## URL·개인정보: 메시지만 차단

대소문자 구분 없이 포함 검사. 원문은 저장·전달·오류 로그에 남기지 않는다.

| 종류 | 검사 기준 / 차단 예문 |
| --- | --- |
| URL | `http://`, `https://`, `www.`, `.com`, `.net`, `.org`, `.kr`, `.io` 도메인. `https://example.com`, `sub.example.kr/a` |
| 주민등록번호 | 날짜 모양 6자리 + 성별 1~4 + 6자리. `000101-1000000`, `0001011000000` |
| 여권번호 | M/S/R/D/O + 숫자 8자리 또는 해당 접두 문자 + 숫자 3자리 + 영문 1자리 + 숫자 4자리. `M00000000`, `M000A0000` |
| 휴대전화 | 010/011/016/017/018/019 + 3~4자리 + 4자리. `010-0000-0000` |
| 일반전화 | 02, 03~06 계열 지역번호, 070 + 3~4자리 + 4자리. `02-0000-0000`, `031 000 0000` |
| 국제 표기 | 국내 접두 0을 `+82`로 대체. `+82-10-0000-0000` |

숫자 묶음 사이 하이픈·공백 1개 또는 구분자 없음 허용. 실제 발급 여부·체크섬은 확인하지 않는다. 전화번호와 구별할 수 없는 숫자열도 차단될 수 있다.

허용 예문: `2026-10-08`, `BPM 120`, `곡 번호 12345`, `시발점`, `성교육`. URL 전체 TLD·난독화·이메일·주소 등 미검토 유형을 자동 확장하지 않는다.
