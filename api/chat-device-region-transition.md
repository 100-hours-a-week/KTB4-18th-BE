# 인증 세션별 지역 이동

B5는 B4의 세션별 참여 조회에 위치 판정 토큰의 sid 검증을 연결한다.
BE `feature/chat-device-region-transition`의 시작 HEAD는 B4 PR #200이 병합된 `0d32aa4`다.

## 계약

`POST /api/v1/locations/resolve`는 검증된 access JWT에 정규 sid가 있으면 그 sid를 위치 토큰 내부에 서명해 넣는다.
응답 JSON·좌표 검증·역지오코딩·지도 도트 검증·5분 유효기간은 유지한다. sid는 요청 필드나 기기 헤더에서 얻지 않는다.

기존 일반 위치 판정과 음악 기록의 사용자·지도 도트 검증은 유지한다.
sid 없는 일반 클라이언트와 내부 호출에는 기존 위치 토큰 발급 경로를 남긴다.
채팅 입장은 `validateForChat`으로 같은 사용자·sid의 토큰만 허용한다.
서명 오류·만료·다른 사용자·다른 sid·무세션 토큰은 400이며 DB 참여 변경 전에 거절한다.
유효한 토큰이어도 대상 방의 지역이 다르면 기존 지역 불일치 오류를 반환한다.

별도 기기 ID·DB 컬럼·migration은 추가하지 않는다. 여기서 기기 경계는 인증 sid이며 물리 장치의 모든 브라우저를 식별하는 기능은 아니다.
기존 무세션 위치 토큰은 채팅용으로 다시 사용할 수 없으므로 현재 위치를 새로 판정해야 한다.
B5를 먼저 적용하고 F2를 연동한다. 이전 FE의 JSON 요청 구조는 그대로 사용할 수 있다.

## 이동 범위

- 이동은 현재 sid의 활성 참여만 대상으로 한다. 다른 sid의 참여·연결·예약·유예는 유지한다.
- 기존 순서대로 유효한 새 지역 입장에서 이전 참여를 종료하고 목적지 정원을 확인한다.
- 목적지가 만석이면 이동한 sid의 이전 참여는 종료된 채 409를 반환한다. 다른 sid는 기존 방에서 계속 전송할 수 있다.
- 같은 방의 다른 sid가 남아 있으면 방별 계정 인원은 줄지 않는다. 다른 방의 인원과 version도 변경하지 않는다.
- 기존 FE는 GPS 두 번으로 이동을 확인한 뒤 현재 참여를 퇴장시키고 새 방을 조회한다. 새 방 조회 실패 시에도 퇴장한 상태를 유지한다. 직접 join API로 존재하지 않는 방을 요청한 경우는 기존대로 참여 변경 전 404다.

일반 퇴장과 로그아웃 정책을 바꾸는 작업은 B6/B7이다. 계정 전체 종료 이벤트의 기존 의미와 제재 처리는 유지한다.
다른 기기의 과거 이력 제공과 UI 캐시 통합도 이번 범위가 아니다.

## 검증

- 원본 Spotless·컴파일 제외 Checkstyle main/test 통과. 테스트 중괄호 규칙 1건을 보완한 뒤 재검증했다.
- 원본 compileJava는 기존 AuthExceptionHandler의 누락 AuthSessionController/LoginQueueController 참조로 차단된다. 해당 오류를 제품 코드에서 수정하지 않았다.
- 격리 사본 `/private/tmp/meomuneum-b5-verify-4p882vpa`에서 위 두 import/advice 대상과 깨진 auth 테스트 디렉터리만 우회했다. 원본 전체 빌드 성공으로 취급하지 않는다.
- TZ=UTC·MySQL 9.7.0에서 채팅·위치·음악 기록·global security 269개 중 263개 통과, 기존 외부 DB 조건부 6개 제외. 사본 bootJar 통과.
- 중괄호 보완 후 최종 입장/연결 통합 25개를 재실행해 전부 통과했다. 원본/사본 Java 324개는 인증 우회 파일 하나를 제외하고 byte가 일치한다.
- 실제 HTTP 위치 판정에서 발급한 토큰의 sid, 다른 sid 재사용 거절, 이동 성공·만석에서 해당 연결만 종료, 남은 연결의 메시지 전송과 인원 유지, 목적지 연결을 검증했다.
- 위치 provider의 외부 응답은 합성 fixture다. 실제 MySQL·JWT·REST·WebSocket·지도 도트 검증을 사용하지만 실제 GPS/외부 역지오코딩 정확도 검증은 아니다.
- 실제 FE의 API wrapper와 chatSessionFetch를 Node에서 실행해 위치 판정→입장→다른 sid 토큰 거절→이동→남은 sid 재입장 ID 유지를 확인했다. 이 fixture의 인증 저장소·토큰 전송 대역을 운영 인증 쿠키/브라우저 잠금 검증과 구분한다.
- 기존 실제 FE 복구 연동도 통과했다. 원본 XML은 `build/b5-region-verification/full/`, 최종 입장 재검증은 `final-entry/`, 집계는 `summary.json`에 보존한다.

실제 휴대전화 두 대·브라우저 GPS 이동·다중 서버·운영 배포는 미실행이다.
JWT 위치 토큰은 기존 5분 유효기간의 판정 증명이며 GPS 위조 방지나 최신 판정 한 건만 허용하는 재사용 방지 정책을 새로 만들지 않았다.
B4로 되돌리면 위치 토큰의 sid 검증 보장이 사라진다. DB 구조는 그대로 유지하며 토큰/참여 이력을 삭제하거나 기존 migration을 수정하지 않는다.
push·PR·운영 DB 적용·배포는 수행하지 않았다.
