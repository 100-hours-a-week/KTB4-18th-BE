# B6 탭별 채팅방 퇴장

## 동작

같은 sid의 탭은 기기 참여 ID를 공유하고, 탭마다 별도의 `view_session_id`를 가진다. 입장 POST는 같은 방의 기존 참여를 반환하는 200 응답에서도 새 열람 세션을 발급한다. 기존 `chat_view_sessions`를 사용하므로 migration은 없다. 입장 예약만으로 메시지 열람 구간이 시작되지 않는다.

메뉴 이동·화면 종료의 DELETE에는 `membership_id`와 `view_session_id`가 모두 필요하다. 서명된 JWT의 sub/sid와 방·참여·열람 세션 소유권을 검사한다. 해당 탭의 열람 구간을 LEFT로 닫고 열람 세션을 영구 종료한 뒤, 그 탭의 연결·구독·예약·단절 유예를 즉시 제거한다. 연결 종료 코드는 4100 CHAT_LEFT다. 같은 sid의 나머지 탭과 다른 sid의 기기는 유지된다. 같은 요청을 반복해도 새 참여를 종료하지 않는다.

실제 연결 인원은 기존대로 방별 계정 수다. 연결 전 입장 예약과 단절 유예는 탭마다 30초이며 다른 탭의 퇴장으로 기한을 연장하지 않는다. 마지막 탭이 명시적으로 퇴장하면 자기 예약은 유예 없이 해제한다. 모든 durable 열람 세션이 종료되고 runtime 참여도 없을 때 기기 참여 행도 종료한다. 응답 유실·단절 후 돌아오지 않은 열람 세션이 남아 있으면 기기 참여 행은 유지될 수 있지만, runtime 예약 만료 후 정원이나 메시지 권한을 점유하지 않는다. 기존 24시간 정리 정책을 유지한다.

명시적 종료된 열람 세션은 재연결·서버 재시작 후에도 사용할 수 없다. 새 화면 입장은 새 위치 판정·입장 응답의 식별자를 사용한다. 예기치 않은 단절은 기존의 30초 열람 복구 및 이후 구간 분리 정책을 유지한다. 기존 view 없는 CONNECT의 구독 시 발급 경로는 유지하지만, 새 FE는 첫 CONNECT부터 입장 응답의 view를 전송한다. 구형 DELETE의 참여 전체 종료 fallback은 제공하지 않는다.

## 지역 이동과의 구분

GPS 재확인으로 이동이 확정된 경우 `POST /api/v1/chat-rooms/{room_id}/region-departures?membership_id=...`에 확인한 `location_resolution_token`을 보낸다. 토큰의 sub/sid가 일치하고 이전 방과 다른 지역일 때만 해당 기기 참여 전체를 종료한다. 다른 기기는 유지된다. 기존 정책처럼 목적지 방 조회 전 종료하므로 조회 실패·만석이어도 이전 지역에 남지 않는다. 단순 메뉴 이동은 이 경로를 사용하지 않는다.

## 적용과 되돌리기

- BE와 FE 계약을 함께 적용한다. 응답에 view가 없으면 새 FE는 입장 실패로 처리하고, view 없는 구형 DELETE는 400이다. API 명세는 `chat-participation.openapi.yaml` 1.3.0이다.
- B2~B5를 전제로 하며 DB 스키마·환경 변수 추가는 없다. 기존 참여·메시지·열람 구간을 백필하거나 삭제하지 않는다.
- 배포 후 같은 sid 두 탭 중 하나의 메뉴 이동, 남은 탭 전송, 마지막 탭 정원 해제, 지역 이동 시 같은 기기 전체 종료를 확인한다.
- 구버전 BE만으로 되돌리면 DELETE가 다시 기기 전체를 종료한다. FE/BE를 함께 되돌리고 기존 연결을 재입장시키는 절차가 필요하다.
- 브라우저 강제 종료·오프라인에서는 keepalive 전달을 보장할 수 없다. 확인된 DELETE는 즉시 퇴장하고, 요청이 도달하지 않은 단절은 기존 30초 유예로 처리한다.
- B7 기기별 로그아웃, B8/B9 계정 이력 통합, F4 전체 모바일 검증은 후속 작업이다.

## 검증

- 실제 MySQL 9.7.0·HTTP·WebSocket과 실제 FE 서비스를 연결한 채팅 172개 전부 통과, 제외 0. 결과: `build/b6-tab-verification/chat-suite/`.
- 동일 sid 복수 탭·다른 sid 유지, 연결 전 예약 정리·마지막 정원 해제, 중복 퇴장·잘못된 소유권, 종료 view 조회 거절, 남은 단절 탭의 복구, 기기별 지역 이동 범위를 검증했다.
- 실제 FE의 두 참여 인스턴스로 메뉴 이탈에 대응하는 stop과 입장 응답 지연 후 정리를 실행하고 남은 탭의 전송을 확인했다. 인증 저장소·GPS는 fixture이며 실제 쿠키·물리 GPS·실기기 검증과 구분한다.
- 최초 통합 실행의 missing view 500은 전용 400 응답으로 보완하고 재검증했다.
- 최종 채팅 회귀 172개 전부 통과·제외 0, 채팅 변경 파일의 Checkstyle 위반 0 및 bootJar 통과. 최종 XML은 `build/b6-tab-verification/final-chat/`에 보존했다.
- 백엔드 전체 회귀는 693개 중 642개 통과·29개 실패·22개 제외다. 실패는 외부 로컬 DB 인증 거절(22개)과 프로필 이미지 테스트의 AuthService 빈 누락(7개)이며 전체 성공으로 취급하지 않는다. 결과는 `build/b6-tab-verification/full-suite/`에 보존했다.
- 최초 추가 오류 상수의 포맷에서 Checkstyle 길이 위반 2건이 발생해 상수 구분을 보완하고 채팅 파일의 최종 규칙 검사를 통과했다.
- 실제 JVM 재시작을 포함한 process 검증은 5개 통과·실브라우저 조건부 1개 제외다. 종료 view는 재시작 뒤 조회 403·CONNECT 4103으로 거절되고 남은 view는 checkpoint까지 복구한다. 결과는 `build/b6-tab-verification/final-process/`에 보존했다.
- 최초 process 검증의 기존 FE harness 실패는 인증 current-token 전송 대역과 기기 전체 종료 기대값을 현재 계약으로 정렬하고 재검증했다. 수정 전 XML은 `build/b6-tab-verification/process-before-fixture-fix/`에 보존했다.
- 최종 원본 전체 Spotless는 기존 인증·설정 5파일의 포맷 위반으로 실패한다. 그 파일들의 자동 변경은 복원·커밋 제외했다. 임시 init script로 채팅 Java 범위만 지정한 Spotless는 통과했으며 저장소 설정은 바꾸지 않았다.
- 최종 원본 Checkstyle main은 통과한다. test에는 기존 `auth/application/LocalMockLoginServiceTest.java:40`의 121자 길이 위반 1건이 있다. 채팅 파일 위반은 0이다. 전체 정적 검사 성공으로 표시하지 않는다.
