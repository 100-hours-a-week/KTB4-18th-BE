## 상위 이슈

- 지역 채팅 다중 탭·기기 정책 반영. 실제 GitHub 번호는 확인 후 연결한다.
- B3는 각 방의 정원을 연결·참여 수 대신 계정 수로 계산한다.

## 작업 범위

- 참여별 예약·연결·재연결 유예를 보존하고 방별 계정을 중복 제거한다.
- 정원 25명에서 같은 방의 기존 계정은 추가 연결을 허용하고 신규 계정은 거절한다.
- 실제 연결 계정 수와 정원 점유 계정 수를 구분한다.
- 기기별 DB 참여 쓰기·지역 이동·탭 퇴장·로그아웃·계정 이력 조회는 후속 작업이다.

## API / 도메인 / 데이터 영향

- REST/STOMP 필드·오류·DB 스키마 변경은 없다. 새 Flyway migration은 필요하지 않다.
- 같은 계정은 방마다 1명이며 여러 참여 중 마지막 예약·유예가 끝나야 자리를 반환한다.
- 현재 인원 이벤트는 실제 연결 계정 수가 변할 때만 방별 version을 증가시킨다.
- 단일 서버의 synchronized/exclusive 임계 구역을 유지한다. FE 수정은 없다.
