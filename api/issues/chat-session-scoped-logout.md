# [BE][TASK] 로그아웃된 인증 세션의 채팅 참여 종료

## 상위 [BE][FEATURE] 이슈

- 상위 이슈: 기존 지역별 채팅 다중 탭·기기 정책 개선 이슈에 연결
- 맡는 결과: 로그아웃한 인증 세션의 채팅만 종료하고 다른 기기의 참여는 유지한다.

## 작업 범위

- 포함: 인증 모듈의 세션별 로그아웃 이벤트 수신, 같은 사용자·sid의 모든 연결·참여·예약·열람 구간 종료, 종료된 sid의 재입장·재연결 차단, 반복 이벤트 처리.
- 제외: 로그아웃 API, access/refresh token·쿠키 폐기, 인증 저장소 변경, 탭 간 인증 상태 전파, 계정 이력 통합.

## API / 도메인 / 데이터 영향

- 내부 계약: 인증 담당자가 검증된 userId·authSessionId로 ChatSessionLogoutEvent를 발행한다. 클라이언트가 보낸 sid를 그대로 사용하지 않는다.
- WebSocket: 4100 / CHAT_LOGGED_OUT으로 해당 세션의 연결 종료. 다른 sid는 유지한다.
- 공개 REST 요청·응답과 DB 스키마 변경 없음. Flyway Migration 불필요.
- 같은 계정의 다른 기기가 남아 있으면 방의 계정 인원은 유지한다.

## 완료 조건

- [ ] 같은 sid의 모든 채팅 탭과 연결 전 예약이 종료된다.
- [ ] 다른 sid의 채팅 송수신과 새 로그인 참여는 유지된다.
- [ ] 종료 이벤트를 반복 수신해도 다른 sid나 새 참여를 종료하지 않는다.
- [ ] 종료된 sid의 재입장·재연결이 거절되고 열람 구간이 종료된다.
- [ ] 관련 단위·실제 서버 통합 테스트와 연동 문서를 남긴다.

## 의존성 및 결정 필요 사항

- 선행: B6 탭별 퇴장 구현.
- 인증 담당자 연동 필요: 세션 폐기 확정 후 위 이벤트 발행. 기존 사용자 ID만 포함한 ChatLogoutEvent는 채팅 종료에 사용하지 않는다.
- 인증 담당자와 이벤트 계약·반영 시점 협의 후 공동 배포한다. 현재 로그아웃 API가 새 이벤트를 발행하기 전에는 실제 로그아웃 연동 완료로 보지 않는다.
- 재시작 이후 폐기 토큰 차단은 인증 모듈의 책임이며, 채팅의 메모리 차단 목록은 이를 대체하지 않는다.
- 실제 상위 이슈 번호·담당자·예상 소요·관련 PR은 등록 시 연결한다.

## 검증 계획

- 단위: 사용자·sid별 차단 범위와 만료, 필수 이벤트 문맥 검증.
- 통합: 실제 MySQL·WebSocket에서 같은 sid 두 탭 종료, 다른 sid 송수신 유지, 예약 해제·중복 이벤트·새 로그인 보존.
- 인증 모듈 연동 후: 실제 로그아웃 API부터 채팅 종료까지 공동 검증.
