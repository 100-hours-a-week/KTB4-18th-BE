# [BE][TASK] 기기별 참여 DB 구조 변경

## 상위 이슈

- 지역 채팅의 다중 탭·기기 정책 반영. 실제 GitHub 이슈 번호는 확인 후 연결한다.
- 같은 계정의 인증 세션마다 서로 다른 지역 참여를 저장할 수 있는 DB 구조를 준비한다.

## 작업 범위

- 기존 참여 테이블에 인증 세션 식별자와 세션별 활성 참여 유일성 제약을 추가한다.
- 기존 참여 ID·시각·종료 기록과 열람 세션의 외래 키를 보존한다.
- 기존 코드가 세션 식별자 없이 저장하는 참여의 사용자별 유일성을 유지한다.
- 입퇴장·정원·지역 이동·로그아웃·이력 조회 로직은 후속 작업이다.

## API / 도메인 / 데이터 영향

- 공개 API·JPA 저장 동작은 변경하지 않는다.
- 새 Flyway Versioned Migration을 추가한다. 적용된 파일은 수정하지 않는다.
- 기기는 물리 장치가 아니라 B1에서 검증한 인증 sid로 구분한다. 과거 sid는 추측해 채우지 않는다.
- 프론트엔드 연동 변경은 없다.

## 완료 조건

- [x] 동일 사용자·서로 다른 sid의 참여와 종료 이력을 저장한다.
- [x] 동일 sid의 중복 활성 참여와 NULL sid의 기존 중복 참여를 거부한다.
- [x] MySQL 9.7.0에서 기존 데이터·열람 관계 보존과 제약을 검증한다.
- [x] 적용·호환성·롤백 제한 및 검증 결과를 기록한다.

## 의존성 및 검증 계획

- B1 인증 세션 식별이 선행하며 현재 브랜치에 병합되어 있다.
- B3/B4의 정원·참여 처리 전에는 sid를 채워 다중 참여를 활성화하지 않는다.
- 실제 MySQL 업그레이드·중복·종료 후 재입장·동시 쓰기·외래 키를 자동 검증한다.
- GitHub 등록과 운영 DB 적용은 이번 요청에 포함하지 않는다.

## 검증 결과

- MySQL 9.7.0 native FK 모드에서 신규 8개·기존 2개 통과. 원본 전체 빌드는 선행 인증 참조 오류로 차단됨.
- 기본 FK 모드의 기존 복합 인덱스 검사 누락은 별도 조치가 필요함. 상세는 ../chat-device-membership-schema.md 참고.
