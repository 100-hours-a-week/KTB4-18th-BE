# [BE][TASK] 기기별 채팅방 참여 분리

## 상위 이슈

- 지역 채팅 다중 탭·기기 정책 반영. 실제 GitHub 번호는 확인 후 연결한다.
- B4는 검증된 인증 sid마다 독립적인 참여를 생성·재사용하고 해당 sid의 연결만 승인한다.

## 작업 범위

- REST 입장의 검증된 JWT sid를 참여에 저장한다. 같은 sid·방의 재시도는 같은 참여를 반환한다.
- 다른 sid는 같은 계정이라도 별도 참여를 사용한다. 정원은 B3의 방별 계정 집계를 따른다.
- CONNECT와 퇴장에서 다른 sid의 참여 사용을 거절한다. 기존 NULL sid를 임의로 차지하지 않는다.
- 기존 전체 종료 경로는 여러 참여를 처리하도록 보완한다. 기기별 로그아웃 정책은 B7에서 변경한다.
- 지역 이동의 전용 흐름(B5), 탭별 퇴장(B6), 계정 이력(B8/B9), FE 변경은 제외한다.

## API / 도메인 / 데이터 영향

- 요청·응답 필드는 유지하며 sid는 검증된 access token에서만 얻는다.
- sid 없는 토큰의 참여 변경은 401, 다른 sid 참여의 CONNECT·퇴장은 거절한다.
- B2 auth_session_id 컬럼을 매핑한다. 추가 DDL·Flyway migration은 필요하지 않다.
- 기존 NULL sid 참여·열람 기록은 보존하고 새 참여와 연결하지 않는다.
